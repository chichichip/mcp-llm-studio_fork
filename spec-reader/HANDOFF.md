# 표준품 선정 에이전트 — 인수인계 문서

> 항공 가스터빈 체결용 표준품(볼트/너트/워셔) 선정 에이전트.
> 이 문서 하나로 맥락을 잡을 수 있게 작성됨. 작업 시작 전 전체를 읽을 것.

---

## 1. 무엇을 만드는가

설계자가 자연어로 요구를 말하면 표준품 부품번호를 선정해 주는 에이전트.

```
사용자: "BOLT, DOUBLE HEX 쓸 건데 직경 .190, 스레드 길이 XX"
   ↓
① 엑셀 표준품 목록에서 카테고리+직경으로 볼트 계열 확정
② 볼트 스펙 판독 → 스레드 길이 조건으로 dash 확정
③ 같은 카테고리의 너트 계열 확정
④ 너트 스펙 판독 → 나사규격 맞는 dash 확정
   ↓
출력: 볼트 부품번호 + 너트 부품번호 + 근거 + 미확인 항목
```

**현재 ①②③④ 중 "스펙 판독" 부분만 구현됨.** 엑셀 연동과 선정 로직이 다음 작업.

---

## 2. 절대 원칙 (항공 부품이라 타협 불가)

| 원칙 | 이유 |
|---|---|
| **VLM 은 판독만. 선정 판단은 결정론적 함수로** | LLM 이 부품을 "고르면" 환각이 곧 비행 안전 문제 |
| **판독값은 자동 검증 통과 후에만 사용** | OCR 오류가 치수 오류로 직결 |
| **모르면 모른다고 출력** | 후보 0개·판독 실패·키 미확정 시 추정 금지 |
| **출력은 짧게** | 사내망에서 사람이 읽고 구두 전달해야 함 |

특히 세 번째. **"MS9555 에 맞는 너트가 없다"를 잡아낸 것이 이 시스템의 가치**였다.
억지로 추천하는 순간 설계자가 신뢰를 거둔다.

---

## 3. 환경 제약 (설계를 좌우함)

- **개발은 외부망, 실행은 사내망.** 코드만 수동 반입.
- **사내망에서 파일 반출 불가.** 실행 결과는 사람이 눈으로 보고 구두 전달.
  → 출력이 두세 줄로 끝나야 한다. 장문 JSON 덤프 금지.
- 외부망에는 VLM 엔드포인트도 실제 스펙 PDF 도 없다.
  → `verify.py` 는 VLM 없이 동작하도록 분리했고, `selftest.py` 로 외부망에서 개발한다.
- VLM: 사내 호스팅 **Gemma**, OpenAI 호환 `/v1/chat/completions`, 인증 헤더 없음.
- 서버에 요청 크기 제한 있음 → 300 DPI 전체 페이지는 413 발생. `--dpi 150` 또는 `--crop` 필요.
- 사내 PC 파이썬 **3.10 / win_amd64**. 폐쇄망이라 whl 수동 반입.
  (Pillow 는 11 부터 3.10 미지원 → **10.4.0** 을 써야 함)

## 4. 도메인 사실 — 조사로 확정된 것

### 4.1 dash 번호의 의미가 표준마다 다르다 ★★

| 표준 | dash 의미 | 나사규격 |
|---|---|---|
| MS9555 | **길이** (-02~-30) | .164-36 UNJF-3A 고정 |
| MS9556 | **길이** (-03~-45) | .190-32 UNJF-3A 고정 |
| AS3477 | **나사규격** (-08=.1640-36, -09=.1900-32) | dash 마다 다름 |
| MS20500 | **나사규격** (1032=#10-32, 428=1/4-28) | dash 마다 다름 |

→ **부품번호만 보고 치수를 추론하면 안 된다. 반드시 표를 읽어야 한다.**
→ 볼트는 대개 길이형, 너트는 대개 나사규격형.

### 4.2 dash 번호가 단조 증가하지 않는다

MS9555: `-26(1.750) → -27(1.875) → -28(2.000) → -29(1.812) → -30(1.938)`
후에 추가된 dash 가 빈 칸을 메운 것. "단조 증가"를 검증 규칙으로 쓰면 오탐.
대신 **"L 이 1/16″ 격자 위"** 를 쓴다.

### 4.3 L − K_max 가 계열 상수다 ★ (핵심 검증 규칙)

- MS9555: **0.578**
- MS9556: **0.630**

나사부 길이가 설계 상수이고 그립(K)이 길이 변화를 흡수하는 구조.
→ 이 값에서 벗어나는 행 = 판독 오류.

**예외**: 짧은 dash(MS9555 -02~-08, MS9556 -03~-09)는 K 가 고정이라
그립이 없고 상수에서 벗어난다. 최빈값 기준 판정으로 자동 분리된다.
이 무그립 dash 는 **전단 하중부에 쓸 수 없으므로** 선정 시 별도 취급 필요.

### 4.4 표 구조의 변형

**식별 컬럼명이 표준마다 다르다**
`DASH NUMBER`(MS9555/9556) / `PART NUMBER`(AS3477) / `SIZE CODE`(AS4395)
→ 프롬프트에서 무엇이라 불리든 `dash` 키로 통일해 받고,
   원래 이름은 `id_column` 으로 별도 보고받는다.

**한 페이지에 좌우 여러 컬럼 그룹**
같은 헤더가 2~3번 반복되며 dash 구간이 나뉜다.
프롬프트에 명시하지 않으면 VLM 이 첫 그룹만 읽고 끝낸다. **가장 흔한 실패 모드.**

**표가 여러 페이지에 걸친다**
- 행 분할: 같은 표가 페이지를 넘어 이어짐
- 컬럼 분할: AS4395 는 TABLE 1A(sheet2) / TABLE 1B(sheet3) 가
  같은 부품의 다른 치수를 나눠 다룸
→ `merge.py` 가 둘 다 처리. 같은 칸을 두 페이지가 다르게 읽으면 충돌로 보고.

### 4.5 짝(볼트↔너트) 규칙 ★

**중분류가 1차 키, 나사규격이 2차 키.**

```
BOLT, DOUBLE HEX  →  NUT, DOUBLE HEX 중분류에서 고름
                  →  그 안에서 나사규격 매칭
```

나사규격만으로 매칭하면 **틀린다**. MS9556(.190-32) 과 MS20500-1032(10-32) 는
나사가 맞지만 MS20500 이 hex 라서 double hex 볼트의 짝이 아니다.
(초기에 이 오판을 했다가 상사 확인으로 정정됨)

**MS9555 는 짝이 되는 너트가 없다.** MS9555 는 .164-36(#8) 인데
MS20500 최소 사이즈는 10-32 다. 이런 케이스를 잡아내는 것이 시스템의 핵심 가치.

### 4.6 재질 / 온도

스펙 본문 REQUIREMENTS 문단에 있다(표 아님).
- MS9555/9556 = AMS5731 (A286)
- MS20500 = 제목에 1200°F 명시, AMS2410 은도금

**엑셀 소재 컬럼은 필터 키로 쓸 수 없다.** `A286`(구체값)과 `CRES`(계열명)이 섞여 있고,
CRES 는 300계열(~800°F)일 수도 A286(1200°F)일 수도 있다.
→ 온도한계는 계열 단위 속성으로 스펙에서 가져와야 한다. `meta` 명령이 이 역할.

### 4.7 워셔는 조인 키가 다르다

워셔는 나사가 없다. **공칭 직경(내경)** 으로 매칭해야 한다.
현재 미구현. 엑셀에 워셔 내경이 어떤 형태로 들어 있는지 미확인.

## 5. 엑셀 표준품 목록 구조

| 컬럼 | 예시 |
|---|---|
| 대분류 | `BOLT` |
| 중분류 | `BOLT, DOUBLE HEX` |
| 도면번호 | `AS9555` |
| 부품번호 | `MS9555-07` |
| 품명 | `BOLT, DOUBLE HEX, 0.164` ← **스펙 파일명과 동일** |
| 소재 | `A286` / `CRES` |
| 비고 | - |

- 한 행 = 부품번호 단위 (dash 까지 포함)
- **품명 = 스펙 PDF 파일명.** 검색 불필요, 결정론적 조회 가능.
  단 파일명에 공백·쉼표가 있어 쉘에서 **따옴표 필수**.
- 대분류 종류: 볼트, 스터드, 스크류, 너트, 워셔, 인서트, 핀, 리벳, 링, 실,
  베어링, 튜빙, 클램프, 브라켓, 피팅, 커플링, 호스 어셈블리

## 6. 현재 구현 상태

```
spec-reader/
├── read_spec.py      메인 CLI
├── verify.py         검증 로직 (VLM 불필요)
├── merge.py          다중 페이지 병합
├── prompts.py        프롬프트 (판독 안 맞으면 여기만 수정)
├── selftest.py       fixture 기반 회귀 테스트
├── fixtures/
│   └── MS9555.json   공개 표준 정답 데이터 (29행)
├── config.example.py → config.py 로 복사 (gitignore)
└── requirements.txt
```

### 명령

```bash
# 치수표 판독 (페이지 자동 탐색)
python read_spec.py read --pdf "BOLT, DOUBLE HEX, 0.164.pdf" --dpi 150 \
    --expect-lk 0.578 --expect-rows 29 --out MS9555.json

# 도면 주기에서 계열 속성(나사규격/재질) 추출 — 계열당 1회
python read_spec.py meta --pdf "..." --out MS9555_meta.json

# 페이지 목록 확인
python read_spec.py preview --pdf "..."

# 외부망 개발용: VLM 없이 검증 로직 테스트
python selftest.py
```

### 검증 상태

- ✅ MS9555 판독 성공 (좌우 그룹 병합 포함)
- ✅ AS3477 판독 성공 (`PART NUMBER` 식별 컬럼 대응 후)
- ✅ `selftest.py` — 정답 통과 + 오독 4종(숫자변조/행누락/null/중복) 전부 검출
- ⬜ `meta` 명령 미검증 — **다음 세션 첫 작업**
- ⬜ 너트 스펙(MS20500 등) 판독 미검증
- ⬜ 컬럼 분할 병합(AS4395) 실제 PDF 미검증

## 7. 다음 작업 (우선순위)

### 7.1 `meta` 명령 검증 — 최우선

도면 주기에서 나사규격을 뽑는 기능. 방금 추가했고 실제 판독 미확인.
MS9555 는 `.164-36 UNJF-3A`, MS9556 은 `.190-32UNJF-3A` 가 나와야 한다.

실패하면 `--crop` 으로 주기 영역만 잘라 시도. 그래도 안 되면
`prompts.py` 의 `META_PROMPT` 수정.

**주기 판독이 불안정하면 대안이 있다**: 너트 표의 THREAD 컬럼에서 직경을 역산해
볼트 직경과 매칭하는 방법. 스펙을 한 번만 읽으면 되어 더 안전하다.
`.190` 과 `10-32` 가 같다는 정규화만 필요.

### 7.2 엑셀 연동 모듈 (`catalog.py`)

```python
find_series(대분류, 중분류, 직경) -> [도면번호, ...]
get_spec_path(품명) -> 파일 경로
nut_category_of(볼트_중분류) -> 너트_중분류
```

**확인 필요**: 중분류 매핑이 단순 문자열 치환(`BOLT`→`NUT`)으로 되는지,
아니면 매핑표를 손으로 써야 하는지. 실제 중분류 값 목록을 봐야 판단 가능.

### 7.3 선정 로직 (`select.py`)

**볼트 dash**: 스레드 길이 조건. 현재 사양은 **직접 비교**.
> 추후 체결두께 기반 2.5산 역산으로 바뀔 수 있음 → 반드시 함수로 분리할 것.
> `L - K` 가 나사부 길이. K 는 범위값이므로 최악값 전파 필요.

**너트 dash**: 나사규격 매칭만. 길이 개념 없음.

**무그립 dash 제외 옵션**: 전단 하중부에는 짧은 dash 를 쓸 수 없다.

### 7.4 에이전트 레이어

LLM 은 **입력 슬롯 추출**과 **되묻기 판단**에만 사용.

되물어야 하는 경우:
- `φ.190` — 나사경/생크경/홀경 중 무엇인지 모호. **추정 금지**
- `nominal .190` — 피치 없음. 같은 직경에 피치가 여럿이면 후보가 갈림
- 후보 0개 / 판독 실패 / 카테고리 미확정

### 7.5 워셔 (후순위)

엑셀에 워셔 내경이 어떤 형태로 있는지 확인 후 착수.

## 8. 미결 사항

- "스레드 길이 XX" 의 최종 판정식 (현재 직접 비교, 변경 예정)
- 너트 표의 알파벳 치수 의미 (C/H/N/T/W) — 도면을 봐야 확정.
  셀프락킹 너트는 볼트 끝이 락킹 요소를 통과해야 하므로,
  T 가 락킹부 두께면 조건식이 하나 더 붙는다.
- 나사규격형 표준(AS3477 류)이 전체에서 몇 개인지
- 중분류 매핑표 실제 값
- 워셔 조인 키

## 9. 참고 — 시행착오에서 배운 것

**엑셀만으로 짝을 찾으려 오래 헤맸다.** 스펙을 읽을 수단(Gemma VLM)이 이미 있는데
"기밀이라 외부 반출 불가"를 "사내에서도 못 읽음"으로 오해한 탓.
→ **엑셀은 색인, 치수 판단은 스펙에서.** 역할을 헷갈리지 말 것.

**나사규격만으로 짝을 판정했다가 틀렸다.** 카테고리가 먼저다.

**검증 규칙은 데이터에서 찾아야 한다.** `L−K_max` 상수성은 표를 관찰해서
발견한 것이고, 이게 없으면 판독 정확도를 측정할 방법이 없다.
새 표준을 추가할 때마다 **그 계열의 불변식을 먼저 찾을 것.**
