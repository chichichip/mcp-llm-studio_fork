# playbooks — 표준품 선정 실행 시트 투입 폴더

표준품(O-ring, 볼트, 베어링 …) **하나당 시트 한 장(.md)** 을 이 폴더에 넣으면,
`mcp_server/standard_server.py`가 그 시트대로 선정을 **한 단계씩** 진행시킨다.

```bat
mcp_server\run_standard_server.bat --list     :: 시트 목록
mcp_server\run_standard_server.bat --lint     :: 시트 점검 (새 시트를 넣으면 먼저 이것부터)
mcp_server\run_standard_server.bat            :: MCP 서버 (HTTP :8093)
```

## 왜 이렇게 하나

지침서를 RAG에 통째로 넣고 도구를 잔뜩 쥐여 주면, LLM이 매 턴 *"지금 어떤 도구를 써야 하나,
어떤 스펙 문서를 봐야 하나"* 를 다시 추론하다 헤맨다. 그래서 순서를 바꾼다.

```
사내 지침서  →  (사내 AI가 1회)  →  선정 실행 시트(.md)  →  standard_server가 단계별 진행
```

시트를 한 번 만들어 두면 그 다음부터 모델은 **고르지 않고 따라가기만** 한다.
단계마다 서버가 "받을 입력 / 쓸 도구 / 볼 표 / 열 엑셀 / 기록할 항목 / 다음에 호출할 도구"를
통째로 찍어 주기 때문이다. 온도·유체 같은 **분기 판정은 모델이 아니라 서버가 계산**한다.

> 자동화 도구가 모든 표준품에 있는 건 아니다(특히 Dash No. 결정). 그런 단계는 시트가
> ```도구 블록으로 "`docs__search_docs`로 이 문서를 찾아라"라고 **지정**만 하고, 실제 스펙
> 읽기는 기존 서버들(rag / office / pdf)이 한다.

## 만드는 순서

1. **사내 AI(nemotron 등)에게 지침서를 읽히고** 아래 프롬프트로 실행 시트를 받는다.
2. 받은 마크다운을 이 폴더에 `<표준품이름>.md`로 저장한다.
3. `mcp_server\run_standard_server.bat --lint`으로 점검한다.
   - `자동판정`으로 표시된 단계가 서버가 계산해 주는 분기다.
   - `산문만`으로 표시된 단계는 모델의 자유 판단으로 남는다(동작은 하지만 헤맬 수 있다).
   - 경고가 나온 곳을 시트에서 고친다.
4. **설계 담당자가 값(규격 번호·온도 범위·엑셀 경로)을 지침서 원문과 대조해 검수한다.**
   사내 AI가 만든 초안을 검수 없이 그대로 쓰지 말 것.

### 사내 AI에게 줄 프롬프트 (그대로 복사)

> 첨부한 표준품 선정 지침서를 읽고, **선정 실행 시트**를 마크다운으로 만들어 줘.
> 아래 형식을 정확히 지켜. 설명은 붙이지 말고 시트 본문만 출력해.
>
> - 맨 위에 `---`로 감싼 메타: `표준품:`, `별칭:`, `지침서:`(문서번호), `버전:`
> - 각 단계는 `## Step 1. 제목` 형식의 제목으로 시작 (번호는 1부터 연속)
> - 각 단계 안에는 그 단계에서 할 일을 **평서문 2~4줄**로 쓰고, 해당하는 것만 아래 블록을 붙여:
>   - ` ```입력 ` — 받아야 할 값. 한 줄에 하나: `이름 | 타입 | 옵션`
>     타입은 `number(단위)` / `choice: 보기1, 보기2` / `text` 중 하나. 옵션은 `필수` 또는 `선택`.
>   - ` ```판단 ` — 조건 분기. `조건:` 한 줄 + `참 ->` / `거짓 ->` 두 줄.
>     조건은 **위에서 정의한 입력 이름**으로 쓴 식: `온도_max <= 204 and 유체 in [Air, Oil]`
>     행동에는 `다음=3`처럼 갈 단계 번호를, 기록할 게 있으면 `선정규격=AS83485`처럼 적어.
>   - ` ```표 <표이름> ` — 지침서에 있는 표(대체규격표 등)를 마크다운 표 그대로
>   - ` ```도구 ` — 이 단계에서 쓸 도구. `도구이름 — 무엇을 찾는지`
>     쓸 수 있는 도구: `docs__search_docs`(사내 문서 검색), `office__read_excel_range`(엑셀),
>     `pdf__read_pdf_text`(DRM PDF), `catia__*`(CAD)
>   - ` ```기록 ` — 이 단계의 결과로 남길 항목. `이름 | 설명`
>   - ` ```검증 ` — 마지막 확인 항목. 한 줄에 하나.
>   - ` ```엑셀 ` — 사내 자동화 통합문서를 쓸 때. `파일:` `시트:` `조회키:` `추출:`
>     시트가 조건에 따라 갈리면: `시트: 장착방식 == Radial -> Sheet2 ; 장착방식 == Axial -> Sheet3`
> - 지침서에 없어서 확실하지 않은 값은 지어내지 말고 `⚠ 확인 필요`라고 적어.
>   (`⚠` 뒤는 주석으로 처리되니 값 뒤에 붙여도 된다)

예시는 같은 폴더의 `example_rubber_oring.md`를 볼 것.

## 시트 형식 레퍼런스

### 메타 (파일 맨 위, 선택)

```
---
표준품: Rubber O-ring
별칭: 오링, O-ring
지침서: MD-WI-004 표준품 선정 지침서
버전: 2026-09-22
---
```

`별칭`에 적은 이름으로도 시트를 찾을 수 있다(`start_selection(playbook='오링')`).

### 단계 제목

`## Step 1. 제목`이 기본이고, `## 2단계 제목` / `### 3) 제목`도 받아 준다.
번호가 단계 식별자이므로 `다음=3`은 `Step 3`을 가리킨다.

### 블록 7종

블록 밖의 글은 전부 **그 단계의 지시문**으로 모델에게 그대로 전달된다.
블록이 하나도 없어도 시트는 동작한다(모델의 자유 판단으로 남을 뿐).

| 블록 | 하는 일 |
|---|---|
| ` ```입력 ` | 그 단계에서 받을 값. 타입·단위·선택지를 서버가 **검증**한다 |
| ` ```판단 ` | 조건식으로 **서버가 분기를 계산**한다 (모델이 판단하지 않음) |
| ` ```표 이름 ` | 참조표. `lookup_table`로 조회된다 |
| ` ```도구 ` | 이 단계에서 쓸 도구를 **지정**한다 (모델이 도구를 고르지 않게) |
| ` ```기록 ` | 이 단계의 결과. 비면 **다음 단계로 넘어가지 않는다** |
| ` ```검증 ` | 체크리스트. 이 단계는 `note` 없이는 제출되지 않는다 |
| ` ```엑셀 ` | 자동화 통합문서 경로·시트·조회키를 구체적 지시로 바꿔 준다 |

#### ```입력

````
```입력
작동유체 | choice: Air, Fuel, Oil, Exhaust | 필수
작동온도_max | number(°C) | 필수 | 과도 상태 포함
작동압력 | number(bar) | 필수
모재 | text | 선택 | 예: Inconel 718
```
````

- `number(단위)`로 선언하면 **단위를 자동 환산**한다. `작동압력=150 psi`로 제출해도
  `10.3421 bar`로 기록된다 (bar/psi/MPa/kPa/kgf·cm²/atm, °C/°F/K, mm/cm/m/inch).
- `choice`는 대소문자를 무시하고 맞춘다(`air` → `Air`). 보기에 없으면 **거부**한다.
- `기본: 값`으로 기본값을 줄 수 있다.

#### ```판단

````
```판단
조건: 작동온도_min >= -30 and 작동온도_max <= 204 and 작동유체 in [Air, Fuel, Oil]
참 -> 선정규격=AS83485; 기본 사양 적용 가능; 다음=3
거짓 -> 기본 사양 적용 불가 — 대체 규격표에서 고른다; 다음=4
```
````

조건식 문법:

- 비교 `>= <= > < == !=`, 논리 `and / or / not` (`그리고` `또는` `아님`도 됨),
  목록 `유체 in [Air, Fuel]`, 사칙연산 `온도_max - 온도_min <= 300`, 괄호
- 이름은 ` ```입력 `이나 ` ```기록 `에 선언한 값. **선언했는데 아직 안 모인 값이 식에
  있으면 서버가 판정을 거부한다** (추측으로 넘어가지 않는다).
- 목록 안의 `Air` 같은 보기 값은 따옴표 없이 써도 문자열로 취급된다.
- `eval`이 아니라 화이트리스트 구문 해석기라, 함수 호출·속성 접근은 거부된다.

행동(`참 ->` / `거짓 ->`)에 쓸 수 있는 것:
`다음=3`(갈 단계) · `완료`(선정 종료) · `이름=값`(기록) · 나머지 문장은 안내 메시지.

#### ```엑셀

````
```엑셀
파일: C:\표준품\MD-WI-004-6-10.xlsx
시트: 장착방식 == Radial -> Sheet2 ; 장착방식 == Axial -> Sheet3
조회키: dash_no
추출: 그루브_폭, 그루브_깊이, 모따기
도구: office__read_excel_range
```
````

서버가 그 세션의 값으로 **시트를 골라** 이렇게 찍어 준다:

```
시트: Sheet3 (조건 장착방식(Axial) == Axial 충족)
조회 키: dash_no = 214
→ office__read_excel_range(path=r'C:\표준품\MD-WI-004-6-10.xlsx', sheet='Sheet3') 로 …
```

엑셀을 여기서 직접 읽지는 않는다. 통합문서 구조가 표준품마다 다르고 매크로가 걸린
경우도 있어서, 읽기는 이미 있는 `office_server`에 맡기는 게 안전하다.

## 진행 방법 (모델이 쓰는 도구)

| 도구 | 등급 | 하는 일 |
|---|---|---|
| `list_playbooks` | 🟢 | 어떤 표준품 시트가 있는지 |
| `show_playbook` | 🟢 | 시트 전문 보기 (`lint=true`로 점검) |
| `lookup_table` | 🟢 | 시트에 실린 표 조회 |
| `start_selection` | 🟡 | 선정 시작 → 1단계 지시 |
| `submit_step` | 🟡 | 값 제출 → 검증·분기 → 다음 단계 지시 |
| `current_step` | 🟢 | 지금 무엇을 해야 하는지 다시 보기 |
| `back_step` | 🟡 | 직전 단계로 되돌리기 (값도 복원) |
| `selection_report` | 🟢 | 선정 결과서 보기 |
| `list_selections` | 🟢 | 진행 중/끝난 선정 목록 |
| `delete_selection` | 🔴 | 세션 삭제 (`confirm=true` 필요) |

진행 상태는 `mcp_server/standard_sessions/`에 JSON으로, 최종 결과서는
`standard_sessions/reports/`에 `.md`로 남는다. 대화가 끊겨도 `current_step`으로 이어서 한다.

## git에 올라가지 않는다

> ⚠ **이 폴더에 넣은 실제 시트는 커밋되지 않는다** (`.gitignore`가 README와
> `example_*.md`만 남기고 제외). 시트에는 사내 규격 번호·문서번호·엑셀 경로가 들어가므로
> 공개 저장소에 딸려 올라가지 않게 한 의도적 설계다. 실제 시트는 사내 AI로 **사내에서**
> 만들어 사내 PC에 두면 된다 — 개인 PC에서 만들어 옮길 물건이 아니다.
